# Фронты E_min(B) для CRK7, CRK8, CCK7(6) — итоги расчётов 2026-10-13

Все расчёты закончены, в статью эти результаты **не внесены** (кроме правок из раздела «Что уже изменено в tex»).

## Что считалось

- `code/front_E.py`: цепочки минимизаций E_{p+1} с мягкой границей max|coef| ≤ B (ρ = 10), как в статье 5–6.
  - Нисходящие цепочки: B = 1000 → 0.45, старт из различных локальных минимумов мультистарта при B = 5.
  - Восходящие цепочки: B = 0.45 → 1000, старт из таблиц статьи.
  - CRK7: 11 цепочек (8 нисходящих, 3 восходящих: CRK7-opt, CRK7s7b, CRK7-B0).
  - CRK8: 9 цепочек (6 + 3: CRK8-opt, CRK8-b, CRK8s9).
  - CCK7(6): 6 цепочек (5 + 1: CCK7(6)).
  - Результаты: `data/front_E.json` (CRK7, CRK8), `data/front_E_CCK7.json`.
- **Нормировка max|coef|.** Минимизация штрафует ненормированные модули, а инертные Im b₁, Im b₂, Im b₃ (вещественные стадии) раздувают max|coef|. Например, минимум CRK7 с E = 6.297e-5 имеет «3.82», а после нормировки 1.31. Поэтому:
  - `front_E.py --norm` добавляет поле `maxcoef_n` во все точки фронтов и в `Emin_*.json`;
  - фронт строится по `maxcoef_n`: E_min(B) — наименьшее E по всем точкам всех цепочек и мультистарта при B = 5 с `maxcoef_n` ≤ B.
- Отчёт по фронтам: `python code/front_report.py [CRK7 CRK8 CCK7]`.
- Дрейф при больших B (CRK7): `code/drift_large_B.py` → `data/drift_CRK7.json`, `data/drift_CRK7.log`.
- Измеренные константы кандидатов (45 знаков, процедура `measure.py`):
  - `code/measure_front.py` → `data/measured_front.json`, `data/front_candidates.json` (коэффициенты уточнены до 60 знаков, невязки ~1e-48);
  - сравнение: `code/compare_front.py`.
- Полировка CCK7 при B = 5: `code/polish_rounds.py`, `optimize_E.py`. Файлы: `data/Emin_87_76_5_front*.json`, `data/Emin_87_76_5_pol_r1.json`, `data/Emin_87_76_5_final.json`.
